Overview

What We Built

This project implements SmolVLA (a compact Vision-Language-Action model) on a real SO-101 6-DOF robotic arm to perform language-conditioned pick-and-place.

The robot learns to pick up a box and place it in one of three colored bowls (red, green, blue) based on natural language instructions. SmolVLA's VLM backbone semantically grounds language — "the ocean-colored bowl" maps to blue, "the grassy bowl" maps to green.

We extended this with voice control (Whisper STT), intent classification (sentence-transformers), and an experimental RL fine-tuning pipeline (RLT).

The Task

Pick Up Box, Place in Bowl

"Place it in the blue bowl"
"Place it in the green bowl"
"Place it in the red bowl"

Given a natural language instruction, the robot must: visually locate the box, grasp it, lift and transport it, then place it into the correct colored bowl and release.

Semantic Grounding

SmolVLA doesn't just match keywords — it understands meaning:

"Put it in the bowl colored like the ocean"Picks box → blue bowl (semantic)

This is the power of vision-language pre-training The model was only trained with literal color names ("red bowl", "green bowl", "blue bowl"), yet at inference time it correctly interprets metaphorical descriptions. Zero-shot generalization from the VLM backbone.

Step 3

Inference & Deployment

The trained model deploys on Mac M4 Pro using MPS acceleration. The robot runs at 30 Hz, taking camera images and outputting action chunks of 50 steps.

How Action Chunking Works

The model predicts 50 future joint positions at once. These are queued and executed one per control step. Only when the queue empties does the model run again. This produces smooth, continuous motion.

Action Chunking Pipeline (predict_action) Step 1: Policy generates 50-step action chunk [a1, a2, a3, ... a50] // 50 joint position targets Step 2: Actions queued in a deque Queue: [a1, a2, a3, ... a50] Step 3: Each control step (33ms at 30Hz) pops one action Step t=0: send a1 Queue: [a2, a3, ... a50] Step t=1: send a2 Queue: [a3, ... a50] ... Step t=49: send a50 Queue: [] (empty!) Step 4: Queue empty → generate new chunk Policy forward pass → new [a1', a2', ... a50'] CRITICAL: Use predict_action() — NOT sample_actions() every step!
The Biggest Inference Mistake Calling sample_actions() every control step and using action[0] generates a new 50-step trajectory every 33ms. The robot always jumps to the start of a new trajectory — causing violent jerking. Use predict_action() from lerobot.utils.control_utils.

Voice

Voice-Controlled Inference

A background thread continuously listens via Whisper STT. When you speak a new instruction, the robot's behavior changes on the very next control step — no stopping, no episode boundaries.

The robot runs autonomously for up to 60 minutes. Just speak to redirect it.

# Voice mode
python voice_inference.py

# Text mode (keyboard)
python voice_inference.py --text_mode

# Custom initial task
python voice_inference.py \
  --initial_task "Pick up the box \
    and place it in the red bowl"

Intent

Intent Classification System

For robust voice control, we map free-form transcripts to canonical task strings using sentence-transformers semantic similarity. This ensures the exact training-time task string reaches SmolVLA, even from noisy speech.

Intent Classification Flow Voice Input: "put it in the leafy one" | v Whisper STT → "put it in the leafy one" | v Sentence Transformer (encode to embedding) | v Cosine Similarity vs. Reference Embeddings: +-- "green", "green bowl", "color of grass", "leaves", "emerald" +-- "blue", "blue bowl", "color of sky", "ocean", "sapphire" +-- "red", "red bowl", "color of blood", "fire", "ruby" | v Best match: "green" (similarity: 0.87) | v Canonical: "Pick up the box and place it in the green bowl" | v SmolVLA inference with exact training-time task string

Advanced

RLT: Reinforcement Learning from Trajectory

Beyond imitation learning, we implemented the RLT approach: using SmolVLA's frozen embeddings as features for an RL actor-critic that handles precision phases (grasping, exact placement) where the base VLA struggles.

RLT: 2-Stage Architecture STAGE 1: Encoder-Decoder (offline) STAGE 2: Online RL + Human Intervention SmolVLA (frozen) Robot runs VLA autonomously | | v v VLA embeddings Human grabs leader arm | to intervene when needed v | RLT Encoder --> z_rl v | (compact) Transitions → Replay Buffer v | RLT Decoder --> reconstruct v Actor-Critic RL updates Loss: 0.707 (converged) (PPO/TRPO style) INFERENCE: VLA ↔ Actor Switching (SPACE key) VLA handles easy parts (approach, positioning) | press SPACE v RL Actor takes over for precision phase (grasping, exact placement) | press SPACE v Back to VLA

Debugging

10 Critical Integration Bugs & Fixes

Integrating SmolVLA with real hardware involved solving these non-obvious bugs. Documented for anyone attempting similar work.

#1 State Vector Order (THE BIGGEST BUG) Building the state with sorted() on joint names produces alphabetical order, but the model was trained with motor-definition order. Per-element normalization applies to the wrong joints → garbage model input → erratic motion.
Fix: Build state explicitly using JOINT_NAMES order.
#2 Action Chunking Calling sample_actions() every step generates a new trajectory each 33ms. Robot always jumps to the start → violent jerking.
Fix: Use predict_action() from lerobot.utils.control_utils.
#3 Do NOT Call .float() on SmolVLA .to(device).float() converts the model to float32, changing numerical behavior and producing wrong outputs.
Fix: Just .to(device) — no .float().
#4 Features Not Populated by from_pretrained SmolVLAPolicy.from_pretrained() doesn't set input_features/output_features.
Fix: Manually set features using PolicyFeature.
#5 Missing Preprocessor/Postprocessor Without normalization stats, model outputs are in normalized space — meaningless to the robot.
Fix: Load from checkpoint via PolicyProcessorPipeline.from_pretrained().
#6 Camera Rename Map Required Camera names webcam/arm_cam don't match policy expectation camera1/camera2.
Fix: Use rename map in both training and inference.
#7 Camera Resolution Non-native resolutions fail. Capture at 640x480 — SmolVLA's preprocessor handles resizing internally.
#8 Episode Length Too Short Default 50 steps = 1.7s. Pick-and-place needs 30-50s.
Fix: --steps_per_episode 1500
#9 torch.load Allowlist RLT checkpoint contains NormalizationMode enum blocked by weights_only=True.
Fix: torch.serialization.add_safe_globals([NormalizationMode])
#10 LeRobot Import Paths It's so_follower, not so101_follower. Check import paths carefully.
The Golden Rule Use predict_action() from lerobot.utils.control_utils — the exact same function lerobot-record uses. Don't reimplement the pipeline.

Takeaways

Key Learnings

What Worked

Semantic Grounding Is Real

Training with literal colors generalizes to metaphors ("ocean" → blue). VLM pre-training delivers.

45 Episodes Is Enough

With SmolVLA's pretrained backbone, ~45 demos sufficed for reliable 3-target pick-and-place.

Cloud Train, Local Deploy

2 hrs on A100, deploy on M4 Pro. HuggingFace Hub makes the handoff seamless.

What Was Tricky

State Vector Ordering

Silent corruption with no error message. Alphabetical vs. motor order — the most destructive bug.

Action Chunking

The difference between smooth and violent jerking is one function call: predict_action().

Normalization Pipeline

Without exact preprocessor/postprocessor from the checkpoint, actions are meaningless numbers.

RL on Top of VLA

Actor-critic needs careful gradient clipping. Critic loss exploded to trillions without it.

Advice for Future Projects

  1. Use the framework's own inference pipeline. Don't reimplement predict_action(). There are dozens of subtle details you'll get wrong.
  2. Capture at native camera resolution. Let the model's preprocessor handle resizing.
  3. Print and verify joint order explicitly. Never rely on dictionary iteration order.
  4. Use cloud GPUs for training. A 2-hour A100 session costs less than a coffee.

Reproduce

How to Reproduce This Project

Prerequisites

  • Mac with Apple Silicon (M1-M4) or Linux with CUDA GPU
  • SO-101 follower + leader arms
  • 2 USB webcams (overhead + wrist)
  • Python 3.10+, HuggingFace account
  • RunPod or similar cloud GPU (24GB+ VRAM)
  1. Clone and set up LeRobot 
    git clone https://github.com/huggingface/lerobot.git
cd lerobot && pip install -e ".[smolvla]"
pip install openai-whisper sounddevice sentence-transformers
  2. Calibrate hardware 
    lerobot-find-port
lerobot-calibrate --robot.type=so101_follower --robot.port=PORT --robot.id=my_follower
lerobot-calibrate --teleop.type=so101_leader  --teleop.port=PORT --teleop.id=my_leader
  3. Record 45 demonstrations 
    ./record_box_to_bowl.sh red    # 15 episodes (creates dataset)
./record_box_to_bowl.sh green  # 15 episodes (appends)
./record_box_to_bowl.sh blue   # 15 episodes (appends)
  4. Train on cloud GPU (~2 hrs on A100) 
    bash train_smolvla_box_bowl_runpod.sh
  5. Run inference 
    ./run_inference.sh              # Autonomous mode
python voice_inference.py       # Voice control
python intent_inference.py      # Intent classification
